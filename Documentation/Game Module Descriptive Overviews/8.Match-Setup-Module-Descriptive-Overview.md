# Match Setup Module — Descriptive Overview

> **Project:** Grid-Based Strategy Game  
> **Module:** 08 — Match Setup System  
> **Document type:** Module design explanation  
> **Status:** Draft for review

## Module purpose

The Match Setup Module prepares two valid armies and their private formations before combat begins. It brings race selection, roster availability, points, team capacity, unit choice, formation editing and Ready states into one pre-match flow.

Its final responsibility is to produce a complete, validated setup that Match Runtime can reveal and turn into a live battle.

## What the Module owns

The Module owns:

- Race selection for each player.
- Available-roster presentation.
- Army point allowance.
- Team-capacity allowance.
- Unit selection and removal.
- Army validation.
- Private formation editing.
- Player-relative deployment coordinates.
- Ready and unlock states.
- Simultaneous reveal preparation.
- Setup-specific diagnostics.

It does not own:

- Which units belong to a race or when they unlock.
- Unit combat data.
- Arena-cell geometry.
- Runtime occupancy.
- Turn order.
- Combat actions.
- Victory conditions.

## Setup flow

The intended player flow is:

1. Select a fantasy race.
2. View the units currently available from that race.
3. Add units while observing points and capacity.
4. Remove or replace units freely before confirming.
5. Arrange the chosen army privately on a compact formation Grid.
6. Select Ready.
7. Wait for the opponent.
8. Validate both complete setups.
9. Convert both formations into authoritative arena coordinates.
10. Reveal both armies simultaneously.

Combat cannot begin with only one army placed or with an invalid setup.

## Army construction

Players build an army under two complementary restrictions.

### Army points

Points represent the overall value of the chosen force. Expensive units consume more of the match allowance and require trade-offs elsewhere.

### Team capacity

Capacity limits the number or battlefield weight of units that can be fielded. It prevents players from filling the arena with an excessive number of inexpensive units and allows large or unusual classes to consume more space in army construction.

The interface should always show:

- Total allowance.
- Amount currently used.
- Amount remaining.
- Whether the next unit can be added.
- Why a choice is unavailable.

## Roster availability

Race & Roster supplies the units available for the selected race and progression level. Match Setup filters and displays those results for the current match rules.

A locked unit should either be hidden or shown with a clear unlock explanation. It must not appear selectable and then fail without explanation.

## Private formation editor

Each player arranges the selected army privately on a compact representation of their deployment zone.

The formation editor should:

- Present the player from their own perspective.
- Show only valid deployment cells.
- Support drag and drop.
- Prevent overlapping units.
- Show unit names or portraits.
- Allow free repositioning before Ready.
- Make the forward direction obvious.
- Display remaining unplaced units.
- Confirm when every required unit is placed.

Team B uses the same player-facing editor orientation. Its formation is rotated into authoritative coordinates during final conversion.

This allows both players to arrange their force naturally with the opponent conceptually ahead of them.

## Ready and locking

Selecting Ready confirms the current army and formation.

Expected behaviour includes:

- Ready is unavailable while the army or formation is invalid.
- Ready locks editing for that player.
- The opposing formation remains hidden.
- A player may unready only if the match has not entered final reveal and the match rules permit it.
- The interface clearly shows whether the local player is ready and whether it is waiting for the opponent.

The battle Grid remains empty during private setup.

## Simultaneous reveal

When both players are ready, Match Setup produces a combined placement request.

The Grid validates both formations together and places them atomically. Either every unit from both armies is accepted or nothing is placed.

A failed reveal returns setup to a safe state with a clear reason. Partial formations must never appear on the battlefield.

## Setup data

Runtime setup data may contain:

- Match rules reference.
- Selected Arena Profile.
- Player identities.
- Selected race per player.
- Race level or availability context.
- Chosen Unit Definition references.
- Points and capacity totals.
- Private player-relative formations.
- Ready states.
- Validation results.

Pending private formations remain outside the Grid until final reveal.

## Match Rules assets

A reusable Match Setup Rules asset may describe:

- Army point allowance.
- Team-capacity allowance.
- Minimum and maximum units.
- Required unit or commander rules.
- Permitted races or roster restrictions.
- Arena Profile options.
- Setup timeout rules when introduced.

The first version should use one clear rule set rather than adding unused configuration.

## Bespoke Setup Simulator

A development tool should allow complete setups to be tested without navigating the final menus.

It should support:

- Selecting two races and test levels.
- Building both armies.
- Adjusting points and capacity.
- Editing both private formations.
- Testing Ready and unready states.
- Previewing coordinate rotation.
- Submitting the combined reveal.
- Inspecting validation failures.
- Saving useful test setups.

The simulator should use the same validation services as the real setup flow.

## Debugging and diagnostics

Diagnostics should display:

- Selected races.
- Available roster entries.
- Chosen units.
- Point and capacity totals.
- Unplaced units.
- Formation coordinates.
- Converted authoritative coordinates.
- Ready states.
- Validation failures.
- Reveal request status.
- Atomic placement result.

Private opponent information must remain protected in real multiplayer presentation even if development tools can inspect it locally.

## Expected player experience

Army building should feel creative but controlled. Players should understand the trade-off between elite units, larger basic forces and specialised compositions.

Formation editing should be quick and tactile. Ready should feel like a meaningful commitment, and the simultaneous reveal should create the first moment of tactical discovery without granting either player a placement advantage.

## Module completion outcome

The Match Setup Module is complete when the project can:

- Select a race for each player.
- Show the correct unlocked roster.
- Build armies under points and capacity.
- Explain unavailable choices.
- Arrange formations privately.
- Validate every chosen and placed unit.
- Lock valid setups through Ready states.
- Keep the battle Grid empty before reveal.
- Convert player-relative formations correctly.
- Place both armies atomically.
- Hand a complete setup to Match Runtime.

The finished Module transforms roster content and player choices into a fair, valid and fully prepared battle.
